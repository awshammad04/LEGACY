# Shared Gemini storytelling — verification, 14 November 2026

All four missions now use Mission 03's recorded Gemini narration workflow and story card through one shared player. The safe checkpoint made before this work is `6419f63` (`Upgrade Mission 1 lunar rover and camera-relative EVA movement`). The existing Vercel production deployment has not been changed.

## Reused implementation

Mission 03 already used pre-generated Gemini text-to-speech MP3s, generated by `scripts/generate-stories.mjs` from `src/content/stories.json`, with the Charon voice. It did not make live Gemini requests from the game. Its original story card created an audio element and remembered explored sites; routine Mission Control speech used a separate browser speech-synthesis path.

This change preserves that pre-generation architecture, configuration, MP3 encoding and all 12 original bilingual site stories. All 24 original audio files are byte-for-byte identical to checkpoint `6419f63`. Forty new recordings add 20 short stories in both languages, using the same Charon voice. The complete catalogue has 32 stories / 64 recordings, about 11.6 MB of audio; the new recordings account for about 4.46 MB and load on demand.

The existing configured Gemini model is tried first. The original Gemini fallback family is retained for quota/model availability, with the successful model recorded per asset. The newer 3.8 API separates style metadata from the spoken transcript; older fallback models use the existing generateContent API. See Google's [official speech-generation documentation](https://aistudio.google.com/docs/speech-generation).

## Gameplay and scientific boundaries

- Each new mission run has its own introduction. A real readiness review can explain engineering tradeoffs; an accepted launch starts the shared clearance story. Rejected launch attempts do not narrate a launch.
- Missions 01–03 retain their original approach-to-site stories, discovery history and T/click replay. These cover Apollo 15, lunar exploration, Jezero science and Opportunity's legacy. A first recorded observation and a submitted report select the appropriate mission's discovery and ending.
- Mission 04 adds actual pointing, recorded-image, acquired-spectrum and three-distinct-night light-curve triggers. The spectrum story requires a spectrum; repeated images on one night do not trigger the three-night story.
- Actual pending hazards and accepted protective/unsafe choices select Mission Control stories. The exact hazard and effects remain visible in the existing gameplay interface. Automatic site stories cannot interrupt an active control warning.
- Narration uses reviewed project content and registered NASA sources. Potential biosignatures are explicitly not proof of life. Telescope results and mission limits are described as the game's simplified model. Endings ask players to review their actual findings rather than asserting an unearned success.
- Routine cues have a 12-second cooldown and do not interrupt an active story. Story history suppresses automatic repeats. Explicit replay remains available. Story history is separate from mission saves and never dispatches a gameplay action.

The shared player releases the previous audio source on a scene, mission or language change. Language changes open the same transcript in the selected language, ready for an explicit click. Autoplay denial leaves a working Listen button. Missing or failed recordings retain the approved text and do not block gameplay. Replay reuses the current audio element; pause/resume retain its playback position. Full transcript text remains available in both languages, including RTL Arabic.

## Security, caching and generation

The existing key remains private in ignored `.env.local` / the existing generation environment. No new key, AI provider, frontend environment variable, runtime endpoint or deployment credential was introduced. The game only requests static MP3s; deploying these recordings does not require a Gemini key in the browser or a runtime Gemini service.

The generator reads voice/model from the original configuration. It checks transcript and audio hashes before reusing a file, saves metadata with each successful recording and never runs automatically during the application build. It caps requests at 64 by default (hard ceiling 100), spaces them at least five seconds apart, bounds retries and handles quotas/timeouts without printing credentials, response bodies or raw network errors. Failed generation retains verified text. Playback URLs contain a recording hash for cache invalidation; edited transcripts refuse stale audio.

Useful commands:

```text
npm run check:stories
node scripts/generate-stories.mjs --max-requests 0
node scripts/generate-stories.mjs --only m1-intro --max-requests 4
```

The zero-request cache check returned `generated: 0, cached: 64, failed: 0, requests: 0`. Offline validation confirmed all 64 transcript, voice and file hashes. A private-value scan found no existing Gemini key in source, public assets, the production bundle or tracked files. Environment files are untracked, and no Gemini request endpoint or key configuration appears in the frontend bundle. All four browser playback tests observed zero Gemini API requests.

## Limits

Narration remains pre-generated, as in Mission 03. Changing a transcript requires regenerating its recording; until then, verified text is shown. Routine Mission Control guidance remains text so every UI update does not become another spoken interruption. Browser checks cover this Windows/Edge setup; they verify playback and transcript integrity, rather than an exhaustive pronunciation review of every recording. The current Vercel deployment remains unchanged.
